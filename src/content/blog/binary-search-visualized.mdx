## The idea

Binary search finds a value in a **sorted** array by repeatedly halving the range it still has to look at. Each comparison throws away half of what is left, so even a billion values need at most 30 comparisons.

## How each step works

Keep two indexes, `lo` and `hi`, around the part of the array that might still contain the target. Then repeat:

1. Look at the middle element, the <Hl c="purple">mid</Hl>.
2. If it equals the target, you are done, and the cell turns <Hl c="green">green</Hl>.
3. If it is smaller than the target, everything to its left is smaller too, so move `lo` past it.
4. If it is larger, move `hi` before it.

When `lo` passes `hi`, the value is not in the array.

```java
static int binarySearch(int[] values, int target) {
    int lo = 0, hi = values.length - 1;
    while (lo <= hi) {
        int mid = (lo + hi) >>> 1; // unsigned shift avoids int overflow
        if (values[mid] == target) return mid;
        if (values[mid] < target) lo = mid + 1;
        else hi = mid - 1;
    }
    return -1;
}
```

<Callout kind="tip" title="Why (lo + hi) >>> 1">
For very large arrays `lo + hi` can overflow a signed int. The unsigned shift treats the sum as unsigned before halving, which gives the right midpoint.
</Callout>

## Why databases care

| values | worst-case comparisons |
| --- | --- |
| 1,000 | 10 |
| 1,000,000 | 20 |
| 1,000,000,000 | 30 |

A B-tree index applies the same halving idea inside every node, and adds a very wide fan-out so the tree stays only a few levels deep on disk. That is the next article in this series.
